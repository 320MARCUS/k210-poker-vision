# K210 Poker Vision 工程复盘

## 1. 为什么重做

原始资料看起来完整，实际不能直接作为项目成果：

- `data.yaml` 写了 53 个类别，其中一项是字符串 `59`；
- 前 20 个 source id 对应的标签名与画面牌面不一致；
- 旧 checkpoint 只训练了 2 个 epoch，验证损失从 446.15 降到 314.04，
  但没有 mAP、身份准确率或测试集记录；
- `main.py` 引用了不存在的模型扩展名，没有 52 类映射、置信度策略和可复现日志；
- 两个旧 KModel 的来源无法证明，不能当作个人训练结果发布。

因此第一步不是继续训练，而是建立数据契约和证据边界。项目将源数据保持只读，
在隔离目录中重新审计、训练和部署。

## 2. 数据审计

源包包含 1,285 张图像、1,285 个标签文件和 5,574 个框。审计脚本检查了：

- 图像与标签是否一一对应；
- 重复图像；
- 坐标归一化和越界；
- 每个类别在训练、验证、测试中的覆盖；
- 标签名称与实际牌面的对应关系。

人工 contact sheet 暴露了类别错位：source id 0–18 需要按实际画面重映射，
source id 19 的唯一框无法确认，source id 20 实际是 `10D`。最终保留
1,285 张图和 5,573 个可用框，隔离 1 个异常框，而不是猜一个类别把它留下。

固定编码为 `2C…AC / 2D…AD / 2H…AH / 2S…AS`，划分保持原始的
964 / 193 / 128。测试集只用于最终评估，不参与阈值和 checkpoint 选择。

这一步最重要的经验是：数据错误会穿过所有后续环节。如果不先审计，后续 mAP
只是对错误标签的精确拟合。

## 3. 分辨率与模型选择

最初沿用 215×215 输入以兼容旧 K210 候选模型。该模型测试 mAP@0.5 为
`0.503`，无法稳定区分花色和点数。

提高到 320×320 后，牌面文字占用更多像素，第一版对照达到 test mAP@0.5
`0.689`。随后发现 K210 旧版 ncc 不支持某些动态 padding 和 Slice，于是把
MaxPool 改为零填充、去掉末层 stride-1 pool，并从 COCO backbone 重新训练。
当前保留在 `results/metrics.json` 的 320 桌面模型达到：

- test mAP@0.5：`0.875`
- test mAP@0.5:0.95：`0.541`
- precision / recall：`0.804 / 0.843`
- identity accuracy：`0.857`
- identity coverage：`0.933`
- RTX 4060 推理约 `0.80 ms/图`

训练中使用验证集 mAP 选择 checkpoint 和 identity 阈值。验证 loss 在较早轮次
达到最低后继续上升，但 mAP 仍在改善，所以最终没有用 loss 代替任务指标。

## 4. 从 PyTorch 到 K210

导出链为：

```text
PyTorch checkpoint
  -> ONNX raw output [1, 285, 10, 10]
  -> TensorFlow SavedModel
  -> TFLite
  -> nncase 1.0 KModel
```

PyTorch/ONNX 在 100 张图上的预测类别一致率超过 99%，框 IoU 偏差小于 0.01。
20 张图的 KModel 模拟 mAP@0.5 为 `0.849`，同子集浮点为 `0.870`，没有看到
明显量化崩溃。

真正的限制出现在硬件端。11.18 MB 模型在 MaixPy 0.6.2 上报
`ERR_KMODEL_FORMAT`。继续编译出 5.20 MB 和 3.57 MB 模型后，KPU 分别出现
`ERR_NO_MEM`。板上可用系统堆约 2.38 MB，且 QVGA 摄像头本身还需要内存，
所以“参数体积变小”不等于“启动后可共存”。

## 5. 160×120 实跑路线

为让摄像头、KPU、YOLO2 后处理、绘制和 LCD 同时工作，模型输入改为
160×120，输出矩形网格 `7×10`。物理演示模型大小为 2,089,896 字节，启动日志
确认：

- `/sd` 可挂载；
- KModel 成功加载；
- `init_yolo2` 成功；
- OV 系列摄像头初始化为 QQVGA；
- LCD 能显示牌面、检测框和标签；
- MaixPy IDE 能看到同一检测画面。

现场使用五张牌时，梅花 9 持续无法正确识别。把 identity 阈值从 `0.20`
降到 `0.10` 后，coverage 升到 `0.885`，identity accuracy 却降到 `0.442`。
这意味着模型只是把更多低置信结果强行映射成牌面，用户看到的错误身份会更多，
因此该方案被否决，继续保留黄色 `unknown`。

## 6. e20 参考模型

对 160×120 构造重新训练支路，并在已有 K210 兼容图上微调 20 个 epoch。验证集
结果为：

- mAP@0.5：`0.481`
- identity accuracy：`0.588`
- identity coverage：`0.747`
- 梅花 9 AP@0.5：`0.505`，迁移初态为 `0.292`

e20 KModel 大小为 2,089,896 字节，SHA-256 为
`5ac40f3fe35cff586e10ffaac09d6ed462abeda580c1323dde8ee50842094a10`。
它证明“矩形输入继续微调”能改善验证指标，但在收尾前 USB 连接失效，未完成
物理重新上传和复验。因此 e20 只作为候选发布，不进入默认 SD 包。

## 7. 为什么停止

继续提高梅花 9 的收益需要更多真实拍摄、重新设计输入分辨率、补充 label，
并可能更换更适合 K210 的轻量检测结构。这些工作的技术价值主要在模型研究，
不再是本次“可验证边缘部署作品”的主要缺口。

项目已经完成的复利点包括：

- 能从数据契约角度判断一个检测项目是否可信；
- 能解释桌面模型、量化模拟与板端实测之间的证据断点；
- 能定位串口、固件 API、KPU 内存、摄像头和模型输入约束；
- 能通过阈值对照证明某个“优化”实际上伤害了身份准确率；
- 能在目标已经满足时主动停止，而不是为了数字继续追加投入。

这就是本次停止优化的依据。
